GUIDE / LOCAL PROCESSING

ブラウザ内ローカル変換とは

FileShapeは、選択したPDFを変換のためにサーバーへ送るのではなく、利用者のブラウザ内で解析してEPUBを生成します。

ファイル選択後も変換処理は端末内

PDFを選択すると、ブラウザがファイルを読み込み、専用のWeb Worker内でPDF解析とEPUB生成を行います。FileShapeの変換処理は、PDF本文を変換目的でFileShapeのサーバーへアップロードする構成ではありません。

ローカル処理にする理由

  • PDF本文を変換サーバーへ預けずに済む
  • 変換用ファイルのサーバー保存期間を気にしなくてよい
  • サーバー側で文書内容を解析する必要がない
  • 変換処理の計算資源を利用者の端末側で完結できる

一方で、すべてを端末内で処理するため、処理速度と利用可能メモリは利用している端末やブラウザの影響を受けます。

ファイル容量よりページ数や内部構造が効くことがある

13MBのPDFが必ず軽く、100MBのPDFが必ず重いとは限りません。数千ページの文書、文字や描画命令が非常に多い文書、画像を多数含む文書では、解析中に大きなメモリが必要になることがあります。スマートフォンではOSやブラウザが1つのページへ割り当てられるメモリに上限を設けるため、デスクトップより先に限界へ達する場合があります。

ブラウザごとに限界が違う

同じ端末でもChrome系とFirefox系ではJavaScriptエンジン、PDF処理、ガベージコレクション、Workerのメモリ管理が異なります。そのため、同じPDFでも処理速度や停止し始めるページ数が一致するとは限りません。長時間の停止やタブの再読み込みが発生する場合は、ブラウザがメモリ圧迫を受けている可能性があります。

通信が完全にゼロという意味ではない

「ローカル変換」はPDF本文の変換処理についての説明です。サイトのHTML、JavaScript、フォント等の配信、将来導入するアクセス解析や広告などは通常のWeb通信を行う場合があります。どの情報を扱うかはプライバシーポリシーと広告・アフィリエイトポリシーに記載します。
