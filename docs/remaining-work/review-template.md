## 問題・変更・根拠

どの入力条件で何が起き、今回の変更でどうなるかを説明します。測定した事実、採用した規則、推測、未確定事項を分けます。新規ファイルと既存変更ファイルを列挙し、それぞれ目的を説明します。

## レビュー判定

- [ ] 目的と実装内容が一致し、調査だけを機能完成と呼んでいない
- [ ] sourceの欠落・二重化・推測による確定がない
- [ ] 個別指示書の正例／反例／完了条件を満たす
- [ ] 必要な検証を実際に実行し、未実施・制限を明記した
- [ ] 既存期待値の変更には独立した根拠がある
- [ ] 残る必須の不具合がない、または範囲の限定が明示承認されている

判定：受け入れ／調査チェックポイントのみ／要修正／保留
