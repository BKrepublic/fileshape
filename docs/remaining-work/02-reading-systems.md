# 工程2：縦書き・ルビの表示互換性

## 目的と開始条件

EPUBが規格上正しいことに加え、実際の読書ソフトで文字、ルビ、目次、注記が読めることを確認します。[共通手順](README.md) と工程1のレビューを読み、受け入れ済みの本文構造を使用します。工程1が保留なら既存出力の表示調査だけを先に行い、最終の表示合格は新しい本文構造でも確認します。

現状は [epub-xhtml.ts](../../src/epub-xhtml.ts) がページ方向をinline styleで指定し、外部stylesheet hrefを受け取れます。一方、[epub-package.ts](../../src/epub-package.ts) はCSSファイルを同梱しておらず、package APIからstylesheetHrefを除外しています。リンクだけ追加して、実体やmanifestのないCSSを参照させないでください。

## 2A：表示確認の対象を固定する

1. 検証対象のリーダーを2種類決め、アプリ名・version・OS・表示設定を記録します。初期候補は [Thorium Reader](https://thorium.edrlab.org/) と [calibre E-book viewer](https://manual.calibre-ebook.com/viewer.html) です。利用可能性を確認し、未導入なら環境のインストール手順に従って準備します。未使用のアプリを検証済みとしません。
2. 自作fixture EPUBを用意します。横書き、縦書き、両方向が混在する文書、exactルビ、長いルビ、補助文字、結合文字、Latin／数字／句読点、空白行、未解決注記、目次の階層、空白ページを含めます。
3. 各アプリでEPUBを開き、初期設定のまま確認します。次に文字サイズを小・標準・大へ切り替え、ページ送り／スクロール、目次移動、本文へ戻る操作を試します。設定名が違う場合は実際に使った操作を記録します。
4. Android上の読書互換性を確認する場合は、既存のEPUBリーダーで同じfixtureを開きます。これは後続工程のAndroid変換アプリ開発とは別の検証です。端末が利用できなければ未実施とし、デスクトップ結果で代用しません。

## 2B：資源とCSSを実装する

1. stylesheetの同梱方式を設計します。新規候補は `src/epub-styles.ts` です。CSSの出力経路とOPF登録を一箇所で管理し、本文からの相対リンクをZIP内実体へ向けます。
2. 縦書き／横書きの基本スタイル、段落間隔、見出し、ルビ、注記を定義します。読者が文字サイズ・行間を変更できるようにし、固定高さや絶対配置で本文を切り落としません。
3. 文書全体のページ送り方向と本文のwriting-modeを区別します。混在文書はページの多数決で方向を決めず、採用する文書方針・明示指定・未確定時の扱いを記録してからOPFへ反映します。
4. 文字の回転や全角／半角の置換で不具合を隠しません。句読点や補助文字の表示不良はCSS・読書ソフト・フォントfallbackを切り分けます。フォント埋め込みを追加する場合は、必要性と配布可能な資源を確認して別の変更として記録します。
5. 注記には読者が分かる短い見出しを付け、本文のルビと誤認しない配置にします。reasonの内部値やglyph情報を本文UIへ追加する必要はありません。保存される注記文字列は変更しません。
6. CSS参照、manifest、文字／注記の保存、決定的なpackage生成をテストします。CSS追加に伴うbyte数の増加は新しい実測として記録します。

## 2C：実リーダーで確認する

次の表をアプリごとに埋め、`合格 / 不合格 / 未実施`、実際の操作、結果を記録します。

| 対象 | 操作 | 合格条件 |
| --- | --- | --- |
| 横書き／縦書き／混在 | 各ページを開き順に送る | 意図した方向と順序、文字の欠け・重なりなし |
| exactルビ | 小・標準・大の文字サイズで読む | 親文字との対応が保たれ、本文へ重ならない |
| 補助文字・記号・空白 | 同じsourceをPDF表示と比較 | 欠字や意味を変える置換なし、意図した改行を保持 |
| 見出し・目次 | 親／子項目を選び、本文へ戻る | 実装した参照先へ移動し、本文が重複しない |
| 未解決注記 | ページ末尾を開く | 全注記が読め、exactルビや本文との区別がつく |
| リフロー | ウィンドウ幅と文字サイズを変える | 行やルビが画面外へ消えず、最後まで読める |

fixture全ケースに加え、9 PDFから生成した各EPUBについて冒頭・中間・末尾を確認し、各書籍で利用可能な親／子目次と注記ページを選びます。選択規則と確認したページ／アンカーをローカルに記録し、抽出したsourceの範囲と照合します。これは全5,141ページの目視認証ではなく、全件自動検証を補う明示した範囲の確認です。

## 検証と完了条件

- `npm test`、`npm run verify:epubcheck`、全9 PDFの変換・規格検証が合格。
- CSSを参照する全XHTMLに対して、対応する資源とmanifest項目があり、外部ネットワークに依存しない。
- 選択した2種類のリーダーで上記fixtureと実コーパスの確認が完了し、対象設定で文字の欠落、読めない重なり、誤った目次移動が0件。
- アプリ／version／操作／実測結果／未確認の環境を記録し、既知制限を利用者向けに説明できる。
- 変更前後でsource所有と注記が保存される。CSSで隠しただけの「修正」は不合格。

表示を実際に確認できない場合は、そのリーダーの検証を保留します。規格検証を代わりの合格条件にしません。アプリ依存の不具合は再現fixtureで切り分け、必須環境を対象外に変える場合だけユーザーの判断を求めます。

成果物は同梱CSS、関連実装・fixture、表示確認表、既知制限、[工程レビュー](review-template.md) です。私的PDFのスクリーンショットはローカルに置き、共通の終了条件で削除します。push後は工程3へ進み、画像とルビの変更後に影響する表示項目を再確認します。

規格の確認先：[EPUB 3.3](https://www.w3.org/TR/epub-33/)。リーダーの機能があることと、FileShape出力がそのリーダーで検証済みであることを区別してください。
